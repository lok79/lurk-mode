# Lurk Mode · 发版验收清单

发版（版本号变更）前手工验收的唯一清单：`npm run build` 后开发者模式加载 `dist/`，逐项过。
定位：把竞品差评反推成自己的验收镜子——竞品用户骂什么，我们就把什么变成发版门槛。
来源：需求雷达 2026-W43 人审批准的三张工单（`radar/reports/2026-W43.md` 簇 1/3/5 → `.scratch/lurk-extension/radar-w43-followups/`）。并入并取代 `.scratch/dark-browser/spec.md` §验收标准（原 5 条已吸收进下文 0/一/二/三，原文件保留作规划期记录）。

## 维护

- **何时跑**：发布新版本号前全跑；改 `dark-layer/` 后建议全跑；改 `settings/` 或 popup 后至少跑 §三。
- **怎么记**：文末「验收记录」追加一行；不通过的项到 `.scratch/lurk-extension/<slug>/` 开工单再修。
- **怎么长**：雷达后续周报点名的新站点、自用撞到的新破绽 → 追加进 §一 矩阵。只增不删，过时的行划掉并注明日期。
- **环境**：常规项用日常 profile；T3 用全新 profile（或移除扩展重装）。
- **机器项自动化**：`node scripts/acceptance-run.mjs`（先 `npm run build`，再用 **Chrome for Testing** 加 `--headless=new --load-extension=dist --remote-debugging-port=9222` 起浏览器）。品牌版 Chrome stable 自 137 起静默忽略 `--load-extension`，用它跑会全站假阴性；无头环境部分站点（如阮一峰博客）会被反爬墙拦，拦住就转人工。

## 0 · 老板测试（核心场景，每次必做）

开插件浏览任意资讯站，离屏幕一臂远：1.5 米外路人说不出你在看哪个网站——页面是一片安静的暗色与占位块，没有任何可辨认的品牌色、图片、标题。

## 一 · 覆盖基准集（站点矩阵）

品类第一投诉是「特定网站不生效、要逐 URL 配置」（W43 簇 1，13 条证据 / 跨 6 竞品）。核心承诺「任意网页布局暗色化」就在这批差评点名站点上验证，每站三项检查：**A 主体内容暗色 / B 媒体不暴露（占位块）/ C 布局不破**。

每站通用前提（矩阵里不重复写）：打开即暗，首帧无白闪；刷新仍即暗；popup 全程零配置。

## 二 · 暗色质量标准（真暗色，而非反色）

竞品差评三宗罪：反转媒体、灰度太亮、整体发蓝（W43 簇 3）。反推为三条全局标准，任何站点都应成立。

**Q1 媒体无反转**
- 标准：任何时机，照片/视频不以任何色相出现——原样、反色、压暗半透明都算不合格；占位块完全不透内容（占位块 vs 遮罩的区分见 GLOSSARY）。
- 目测步骤：掘金连滚 3 屏 + 刷新 GitHub 首页 + Pinterest 首屏，全程盯图片区域；再 Peek 一张掘金配图。
- 通过：全程未见任何图片内容（哪怕一帧）；Peek 恢复的是原色，不反色、不被压黑（防首帧乐观样式未移除的回归，机制见 `src/packages/dark-layer/lib/engine.ts` 的 removeEarlyStyle）。

**Q2 灰度层次与对比度开箱即得**
- 标准：不调任何参数（产品也没有参数可调），三级灰可辨——背景（纯黑）/ 次级文字（暗灰）/ 正文（#c9c9c9）；正文久读不刺眼。
- 代表站：阮一峰博客（纯文字长文）、掘金（资讯流卡片）、GitHub（应用 UI + 代码）。
- 目测步骤：各站读一段正文 30 秒；再找时间戳、侧栏等次级信息看一眼。
- 通过：正文与背景边界清晰；次级信息可辨认但不抢焦点；无背景与次级文字黏成一片的死灰。

**Q3 无整体色相漂移**
- 标准：白色背景 → 中性黑，不发蓝、不发绿；品牌色只压明度、不偏色相（红按钮还是暗红，不突变成蓝紫）。
- 目测步骤：google.com 首页（纯白底）开插件看背景；再看 GitHub 绿按钮、掘金品牌蓝。
- 通过：黑是中性黑；品牌色相与原站一致。

## 三 · 交互用例（开关与名单）

**T1 多窗口确定性**（差评："it always picks the other window"）
- 预期（写死）：开关是 `chrome.storage.sync` 里的全局单状态，所有标签页的 content script 监听 `storage.onChanged` 即时热切换（实现见 `src/content.ts`）。任一窗口切换，**所有窗口、所有标签页** 1 秒内跟随，无需刷新；结果只由「全局开关 × 不打扰名单」决定，与在哪个窗口操作无关。
- 步骤：
  1. 窗口 A、B 各开一个掘金标签页（均暗色）。
  2. A 窗口 popup 关全局开关 → A、B 两页同时还原原样，B 不刷新。
  3. 再开 → 两页同时回暗色。
  4. 两窗口各开一个 bilibili 页，在任一页 popup 关站点开关（入名单）→ 两页均原样；掘金页不受牵连。
- 通过：每一步另一窗口 1 秒内跟随；全程零刷新。

**T2 不打扰名单真实豁免**（差评："include and exclusion lists don't work"）
- 预期：名单内站点完全恢复原样——当前页即时还原、刷新后零闪暗（同源缓存 `lurk:state` 保证）；子域继承父域条目；增删即时生效，无需重启浏览器或重载扩展。
- 步骤：
  1. bilibili.com 页面上 popup 关站点开关 → 当前页即时还原。
  2. 刷新 → 直接原样渲染，无黑闪、无白闪。
  3. 新标签开 live.bilibili.com → 原样（子域继承）。
  4. popup 开站点开关（移出名单）→ 当前页即时回暗色；live.bilibili.com 刷新后也暗色。
- 通过：四步全中；全程只用 popup，不碰开发者工具。

**T3 全局开 = 默认全站生效**（差评："add URL for every Page of GMAIL…1 SETTING to rule them all"）
- 预期：全新安装默认开启（`DEFAULT_SETTINGS.enabled = true`），任何普通网站打开即暗；产品不存在逐 URL、逐页面配置入口。
- 步骤：全新 Chrome profile（或移除扩展重装）→ 开发者模式加载 `dist/` → 不碰 popup，依次打开矩阵 #1、#8、#10、#2 四站。
- 通过：4/4 打开即暗；popup 零操作。
