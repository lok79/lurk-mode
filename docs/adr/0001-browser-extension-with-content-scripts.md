# 载体选浏览器插件 + 内容脚本注入，而非 VS Code 或代理改写

产品目标是"工位浏览网页不显眼"。先后评估过三种载体：VS Code 内嵌浏览器、独立原型（服务端抓取改写，见仓库根目录遗留的 `prototype_code_browser.py`，已废弃）、浏览器插件。选定浏览器插件 + 内容脚本（content script）注入方案，因为它在真实页面上运行：SPA（如掘金）、登录态、页面自身脚本全部天然可用，不存在代理方案的抓取超时、反爬、相对地址劫持问题。

## Considered Options

- **VS Code 插件**：受 webview iframe 限制，大站普遍禁止被嵌入，实际只能走代理改写，SPA 无法工作。放弃。
- **代理改写（原型路线）**：需服务端抓取+重写 HTML，存在 SSL 超时、反爬失败、`<base>` 标签导致内部跳转劫持等问题，纯脚本渲染站点（掘金）只剩空壳。放弃。
- **浏览器插件（选定）**：Manifest V3 内容脚本向真实页面注入暗色 CSS 与媒体占位脚本；代价是不能控制浏览器外部、且依赖商店分发，均可接受。
